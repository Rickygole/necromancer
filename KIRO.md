# How Kiro fits into this project

This file is a plain account of what the `.kiro` directory contains and how it was produced. Judges should read it before trusting anything under `.kiro`.

## What is in `.kiro`

- `steering/`: six always-included steering docs (product, tech, structure, COBOL semantics, test integrity, no floats).
- `specs/`: requirements, design and tasks for three features (`uicalc-twin`, `diff-harness`, `workbench-ui`).
- `agents/`: three custom agent definitions (COBOL analyst, migration engineer, failure analyst) with scoped write paths.
- `hooks/`: two hook files (re-derive properties on spec or legacy source edits, and a test guard for the oracle, evidence and decisions).
- `settings/mcp.json`: registers the local oracle MCP server in `oracle_mcp/`.

## How these files were produced

These files were written as plain files alongside the code, not generated by walking through the Kiro IDE spec workflow. The specs were written by hand from the same rules table the twin was built from. The hook files were written to match the hook format and have not been confirmed through the Kiro hook panel.

## What has actually been run in Kiro

- Kiro CLI 3.3.0 was installed and signed in on the owner's Kiro account (free plan).
- `kiro-cli agent list` shows the three custom agents from `.kiro/agents/` and `kiro-cli mcp list` shows the `oracle` server from `.kiro/settings/mcp.json`.
- The `cobol-analyst` agent was run once through the CLI. It read the COBOL source, the probe report, the counterexamples and the twin, and wrote `evidence/analysis/cobol-analyst.json`. Shell commands were denied in non-interactive mode, so the agent did not call the oracle MCP tool. It applied the `parse_record` logic by hand and said so in its own output. The run then ended with a service throttling error. That file is the agent's raw output and has not been reviewed line by line.
- The `failure-analyst` and `migration-engineer` agents were each started twice through the CLI. Each run read files and then ended with the same throttling error, so neither wrote any output. `evidence/classes/` does not exist.
- The oracle MCP server's `parse_record` function was called directly from Python on the first counterexample and decoded both records correctly. That check did not go through Kiro.

## What has not been run in Kiro

- The Kiro IDE has not been used on this repository.
- No spec task has been executed in Kiro.
- The two hook files have not been confirmed in the hook panel and have not been seen to fire.
- The oracle MCP tools have not been called from inside a Kiro session.

## What the oracle MCP server does

`oracle_mcp/server.py` exposes four tools: compile a COBOL file inside the repo, run a batch through the compiled oracle, parse a record into fields, and compile and run a small COBOL snippet as a probe. It runs over stdio only and should never be exposed over a network, because a probe compiles arbitrary COBOL.
